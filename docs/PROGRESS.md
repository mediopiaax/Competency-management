## PROMPT.md 이후에 정해진 것

사용자와 대화로 확정한 내용이다. PROMPT.md와 다르면 이쪽이 우선이다.

1. **여러 기관이 쓰는 서비스다.** 기관마다 자기 인재상·역량 목록을 넣고, 그에 맞는 채점기준표를 만들어 학생을 평가한다. `docs/reference/`의 성균관대 역량 목록은 테스트용 예시일 뿐이며, 특정 기관의 역량명을 코드에 넣지 않는다.
2. **학생도 직접 쓴다.** 학생이 원하는 기관의 역량을 넣고 본인 상태를 점검할 수 있다. 학생도 기관과 똑같이 채점기준표를 확인·수정하고 최종 확정·저장한다. 차이는 평가 대상이 본인 1명이라는 것뿐이다.
3. **자기진단·3품인증은 점수에서 뺀다.** SSCA 학생성공역량진단(31번), 학습경험진단(32번), 3품인증 취득현황(29번)은 채점기준표의 근거 데이터로 쓰지 않는다. 값은 읽어서 점검 화면에 "점수 계산에 쓰지 않음"으로 표시한다.
4. **학생 데이터 양식은 34개 카테고리 공통 양식을 쓴다.** 기관에 없는 항목은 '해당 없음'으로 처리한다. (사용자가 명시적으로 답하지 않아 기본안으로 진행 중)
5. **평가 대상은 학부생이 기본이다.** 대학원 기준값을 따로 둘 수 있게만 만든다. (역량 목록 제목은 "대학원생"이지만 샘플은 모두 학부생. 기본안으로 진행 중)
6. **DB와 로그인은 STEP 3에서 넣는다.** 저장할 것(채점기준표)이 생기는 시점이다. 기관·학생 구분과 기관별 데이터 분리도 그때 들어간다.
7. **AI 모델 기본값은 `claude-opus-5-5`**이고 설정 파일에서 바꿀 수 있게 한다.

## 기술 스택

### 파서 규칙

- **라벨로 읽는다.** 셀 위치가 아니라 `■` 구분 머리, `데이터 상태 ▶`, 항목 라벨, 표의 `No` 머리줄을 찾아 읽는다. 행·열이 밀리거나 표에 행이 추가돼도 읽힌다.
- **학생 시트만 고른다.** `■ 학생 기본정보`가 있는 시트만 읽고, 입력이 하나도 없는 시트는 빈 양식으로 건너뛴다.
- **데이터 상태 판정.**
  - 상태 미선택 → 미수집
  - '값 있음'인데 입력값 없음 → 경고 + 미수집
  - '활동 없음'·'미수집'·'해당 없음'인데 입력값 있음 → 경고 + 미수집
  - 기본정보의 공학인증 대상 계열이 N → 4번 카테고리는 자동으로 해당 없음
- **칸 단위 미수집.** '값 있음' 카테고리 안의 빈칸은 그 칸만 미수집이다. 숫자 0은 측정된 값이다.
- **형식이 틀린 값은 고쳐 읽지 않는다.** "18학점", "약 30시간", "2025.11" 같은 값은 추측하지 않고 그 칸만 미수집으로 처리하고 경고한다. 원문은 보존한다.
- **그 밖의 점검.**
  - 학사 명부(`01_학생목록`)와 학번·이름·학년 대조
  - 시트 이름에 학생 이름이 있는지
  - 개인정보 동의가 N이거나 빈칸이면 평가 제외
  - 만료일이 수집 기준일보다 이른 어학 성적 표시
  - 총 봉사시간과 내역 합계 불일치
  - 0~100 항목에 0~1 비율을 넣은 것으로 보이는 값
- **템플릿 버전.** 원본에 버전 칸이 없어 라벨 구성이 사전과 일치하는지로 판별한다. 다르면 '템플릿 불일치' 오류를 낸다.

### 검증 결과

- 테스트 19개 통과, 타입 검사와 린트 통과.
- API를 직접 호출해 샘플 불러오기, 파일 업로드, 엑셀이 아닌 파일 거부를 확인했다.
- 화면은 페이지 응답까지만 확인했다. 브라우저에서 클릭하는 동작은 사람이 확인해야 한다.

## 알려진 문제·미정 사항

- **디스크 여유 공간 부족.** 개발 컴퓨터의 여유가 1GB 남짓이라 패키지 설치가 한 번 실패했다. DB 추가 전에 공간 확보가 필요하다.
- **기관마다 학생 데이터 양식이 달라야 하는지 미정.** 지금은 공통 양식 하나를 가정한다. 달라져야 하면 필드 사전을 기관별로 두는 설계가 필요하다.
- **템플릿에 성균관대 전용 항목이 섞여 있다.** 3품인증, i-Campus, 공학인증 등. 다른 기관에서는 '해당 없음'으로 처리하는 것으로 가정한다.
