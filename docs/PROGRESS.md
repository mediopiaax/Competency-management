# 작업 진행 상황

마지막 갱신: 2026-10-02

요구사항 원문은 [PROMPT.md](PROMPT.md)에 있다. 이 문서는 그 뒤에 정해진 것과 지금까지 만든 것을 기록한다. 작업이 진행될 때마다 갱신한다.

## 한눈에 보기

역량 목록 업로드부터 평가 결과까지 한 바퀴가 돌아간다. AI 키 없이도 끝까지 동작하고, 키를 넣으면 초안 생성과 서술 판정에 AI를 쓴다.

| 단계 | 내용 | 상태 |
|---|---|---|
| STEP 0 | 분석·설계 | 완료 |
| STEP 1 | 템플릿 파서 + 데이터 점검 화면 | 완료 |
| STEP 2 | 채점기준표 데이터 구조 + 정량 계산 엔진 | 완료 |
| STEP 3 | 초안 생성 + 편집 화면 + 검증 배너 + 버전 저장 | 완료. 단, AI 초안은 실제 키로 호출해 보지 못함. 기준표 엑셀 입출력은 없음(JSON 내보내기만) |
| STEP 4 | 서술 판정(AI) + 인용 검증 + 캐시 | 코드와 테스트 완료. 실제 키로 호출해 보지 못함 |
| STEP 5 | 결과 화면(운영자용/학생용) + 내보내기 | 완료 |
| STEP 6 | 미리보기 채점, 버전 비교, 감사 로그, 권한 | 일부. 미리보기 채점과 작업 기록은 있음. 버전 비교와 로그인·권한은 없음 |

## 실행 방법

```bash
npm install
npm run dev     # http://localhost:3000
npm test        # 테스트 51개
```

Node 22.5 이상이 필요하다(내장 SQLite 사용). 데이터는 `data/app.db`에 저장되고 git에는 올라가지 않는다.

AI를 쓰려면 프로젝트 폴더에 `.env.local` 파일을 만들고 `ANTHROPIC_API_KEY=...`를 넣은 뒤 서버를 다시 켠다.

### 직접 돌려 보는 순서

1. 처음 화면에서 작업 공간을 만든다(기관 또는 학생).
2. **1 역량 목록**: 「샘플 역량 목록으로 보기」 → 열 매핑 확인 → 「이 목록 저장」.
3. **2 채점기준표**: 「기본 초안 만들기」 → 편집 화면에서 확인·수정 → 「저장」 → 「확정」.
4. **3 학생 데이터**: 「샘플 학생 6명 올리기」 → 학생을 눌러 점검 결과 확인.
5. **4 평가·결과**: 「평가 실행」 → 결과 화면에서 역량을 눌러 계산 과정 확인, 운영자용/학생용 전환, 엑셀·JSON 내보내기.

## PROMPT.md 이후에 정해진 것

사용자와 대화로 확정한 내용이다. PROMPT.md와 다르면 이쪽이 우선이다.

1. **여러 기관이 쓰는 서비스다.** 기관마다 자기 인재상·역량 목록을 넣고, 그에 맞는 채점기준표를 만들어 학생을 평가한다. `docs/reference/`의 성균관대 역량 목록은 테스트용 예시일 뿐이며, 특정 기관의 역량명을 코드에 넣지 않는다.
2. **학생도 직접 쓴다.** 학생이 원하는 기관의 역량을 넣고 본인 상태를 점검할 수 있다. 학생도 기관과 똑같이 채점기준표를 확인·수정하고 최종 확정·저장한다. 차이는 평가 대상이 본인 1명이라는 것뿐이다.
3. **자기진단·3품인증은 점수에서 뺀다.** SSCA 학생성공역량진단(31번), 학습경험진단(32번), 3품인증 취득현황(29번)은 근거 데이터로 고를 수 없고, 넣으면 검증 오류로 저장이 막힌다.
4. **학생 데이터 양식은 34개 카테고리 공통 양식을 쓴다.** 기관에 없는 항목은 '해당 없음'으로 처리한다. (사용자가 명시적으로 답하지 않아 기본안으로 진행 중)
5. **평가 대상은 학부생이 기본이다.** (역량 목록 제목은 "대학원생"이지만 샘플은 모두 학부생. 기본안으로 진행 중. 대학원 기준값 분리는 아직 없음)
6. **AI 모델 기본값은 `claude-opus-5-5`**이고 `src/lib/ai/config.ts`나 환경변수 `AI_MODEL`로 바꾼다.

## 구현하면서 정한 것

PROMPT.md와 다르게 했거나 PROMPT.md가 정하지 않은 부분이다.

- **DB는 Prisma 대신 Node 내장 SQLite(`node:sqlite`)를 쓴다.** 개발 컴퓨터의 디스크 여유가 부족해 Prisma 엔진을 설치하기 어려웠다. 저장은 `src/lib/db.ts` 한 파일에 모여 있어 나중에 PostgreSQL로 옮길 때 이 파일만 바꾸면 된다.
- **로그인은 아직 없다.** 처음 화면에서 작업 공간(기관/학생)을 만들고 고르면 쿠키에 기억된다. 데이터는 작업 공간별로 분리되지만 누구나 어느 작업 공간이든 고를 수 있다.
- **AI 없이 만드는 '기본 초안'이 있다.** 역량 목록의 측정지표 문구를 템플릿 데이터에 연결하는 규칙으로 만든다. AI 키가 없을 때와 AI 초안이 검증에 실패했을 때 쓴다.
- **AI 초안은 구조만 정하고 점수 기준은 기본값을 쓴다.** AI는 평가 항목, 근거 데이터, 비중, 유형, 서술 판정 기준문을 정한다. 숫자 구간·선택지 점수는 `src/lib/rubric/presets.ts`의 기본 기준이 들어가고 담당자가 고친다.
- **평가 방식이 근거 데이터마다 붙는다.** PROMPT.md는 평가 항목 한 행에 방식 하나를 가정하지만, 한 항목의 근거들이 단위가 서로 달라(어학 점수와 과목 수 등) 근거마다 방식과 점수 기준을 따로 둔다.
- **방식은 4가지다.** 숫자 구간, 선택지 점수, 서술 판정에 더해 '어학 환산표'를 따로 둔다.
- **가점형의 비중은 "최대 가점(점)"이다.** 기본형 비중 합계 100에 들어가지 않고, 점수 × 비중 ÷ 100만큼 더한다. 상한은 100점이다.
- **'해당 없음' 항목은 충족도 분모에서도 뺀다.** 해당하지 않는 학생이 충족도에서 손해 보지 않게 하기 위해서다.
- **온도 0 대신 판정 캐시로 재현성을 보장한다.** 현재 모델은 온도 설정을 받지 않는다. 같은 글·같은 기준·같은 프롬프트면 저장된 판정을 다시 쓴다.
- **형식이 틀린 값은 고쳐 읽지 않는다.** "18학점", "약 30시간" 같은 값은 추측하지 않고 그 칸만 미수집으로 처리하고 경고한다.
- **개인정보 동의가 빈칸이어도 평가에서 제외한다.**

## 계산 규칙 요약

- **데이터 상태**: 미수집과 해당 없음은 계산에서 빠진다. 활동 없음은 0점으로 들어간다. '값 있음' 안의 빈칸·형식 오류 칸은 그 근거만 미수집이다.
- **평가 항목 점수**: 점수가 나온 근거들 중 최고값(또는 평균). 근거가 하나라도 있으면 평가한다.
- **역량 점수**: 점수가 나온 기본형 항목의 (점수 × 비중) 합 ÷ 그 항목들의 비중 합, 여기에 가점을 더한다.
- **데이터 충족도**: 점수가 나온 기본형 비중 ÷ (전체 기본형 비중 − 해당 없음 비중). 50% 미만이면 판정 보류.
- **반올림**: 중간값은 소수 둘째 자리까지, 최종 점수만 정수로 한 번 반올림한다.
- **검산**: 항목별 기여 점수와 조정값을 더하면 역량 점수와 같다. 결과 화면에 표시한다.
- **서술 판정**: 레벨 × 20점. 정량 점수 대비 ±15점 안에서만 반영한다. 판단 불가는 0점이 아니라 제외다.
- **학기 보정**: 체크한 근거는 값을 이수 완료 학기 수로 나눈 뒤 구간표에 넣는다.

## 검증 결과

- **자동 테스트 51개 통과.** 파서 19개, 계산 엔진·검증 18개, 역량 목록·기본 초안 4개, AI 초안·서술 판정 10개.
- **PROMPT.md의 완료 기준을 테스트로 확인했다.** 같은 입력이면 같은 점수, 기여 점수 합과 역량 점수 일치, 미수집이 0점 처리되지 않음.
- **실제 브라우저(Chrome)로 전체 흐름을 눌러 확인했다.** 작업 공간 생성 → 샘플 역량 목록 저장 → 기본 초안 생성 → 비중을 틀리게 고쳐 저장이 막히는 것 확인 → 다시 고쳐 저장 → 확정 → 잠김 확인 → 새 버전 만들기 → 샘플 학생 6명 업로드 → 평가 실행 → 결과 상세와 학생용 화면. 브라우저 오류는 없었다.
- **AI 호출은 실제로 해 보지 못했다.** API 키가 없어 가짜 응답으로만 테스트했다. 검증·재시도·인용 확인·캐시 로직은 테스트했지만, 실제 모델 응답의 품질과 프롬프트는 확인되지 않았다.

- 학부/대학원 기준값 분리
- 등급 분포 등 요약의 그래프 (지금은 숫자와 역량별 점수 막대만 있음)
- 미리보기 채점에 서술 판정 반영
- 운영 DB(PostgreSQL)

## 알려진 문제·미정 사항

- **기본 초안의 품질은 거칠다.** 예를 들어 '리더십'은 세 세부 요소의 측정지표가 같아서 항목이 하나만 만들어지고, 학생회 직책 하나로 100점이 나온다. 초안은 출발점이고 담당자가 고쳐야 한다.
- **기본 점수 기준과 어학 환산표는 근거 없는 가정이다.** 구간 경계와 점수는 임의로 정한 값이다.
- **디스크 여유 공간 부족.** 개발 컴퓨터의 여유가 2GB 남짓이다.
- **기관마다 학생 데이터 양식이 달라야 하는지 미정.** 지금은 공통 양식 하나를 가정한다.
- **템플릿에 성균관대 전용 항목이 섞여 있다.** 3품 인정, i-Campus, 공학인증 등.
- **AI 거절 대비 설정(fallback)을 넣지 않았다.** 키가 생기면 실제 호출로 확인하면서 넣는다.
